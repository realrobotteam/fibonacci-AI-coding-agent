# Fix: Long-Prompt Crash — Context Window Management

**Bug**: The extension crashes or hangs when the user sends a long prompt or the conversation grows large. Root cause: `messages` grows unbounded in `agentLoop.ts` with no token-budget enforcement. Tool results contain full file contents; `buildMessages()` re-sends the entire history every iteration; `pushFullState()` floods the webview; and the `contextCompression` setting is dead code (read but never used).

**Files modified**:
- `src/core/agentLoop.ts` — add token-budget trim before each API call
- `src/webviewProvider.ts` — throttle/paginate history pushes to webview

## Fix Design

### 1. Token-budget gate in `agentLoop.ts`

Add a lightweight heuristic (~1 token per 4 chars for English-heavy content; use `content.length / 3.5` as a reasonable approximation). Define a budget of **120 000 characters** (~30K tokens) for the API message array. Before each `this.deps.client.chat()` call, trim `messages` from the front (oldest) until under budget.

**Eviction rules** (preserve conversation coherence):
1. Drop full tool-result messages that are >5 messages old, replacing them with a 1-line stub: `[Tool result for <name> dropped — <N> chars]`.
2. If still over budget after dropping all eligible tool results, drop oldest non-system messages one by one.
3. Never drop the most recent 3 user/assistant exchanges (last 6 messages).
4. Never drop the system prompt.

```ts
// In agentLoop.ts, just before const response = await this.deps.client.chat(...)
const BUDGET = 120_000; // chars ≈ 30K tokens
const MIN_RECENT = 6;   // keep last 3 user+assistant pairs

messages = enforceBudget(messages, BUDGET, MIN_RECENT);
```

`enforceBudget` implementation:
```ts
function enforceBudget(
  messages: ChatCompletionMessageParam[],
  budget: number,
  keepRecent: number
): ChatCompletionMessageParam[] {
  // Fast path — under budget already
  const totalLen = messages.reduce((n, m) => n + (m.content?.length ?? 0), 0);
  if (totalLen <= budget) return messages;

  const result = [...messages];
  const system = result[0]?.role === 'system' ? result.shift()! : null;

  // Pass 1: compress old tool results
  for (let i = 0; i < result.length && result.reduce((n, m) => n + (m.content?.length ?? 0), 0) > budget; i++) {
    const m = result[i];
    if (m.role === 'tool' && i < result.length - keepRecent && (m.content?.length ?? 0) > 200) {
      const name = (m as any).toolName ?? 'tool';
      result[i] = {
        role: 'user',
        content: `[tool result for ${name} dropped from context — ${(m.content?.length ?? 0).toLocaleString()} chars]`,
      } as ChatCompletionMessageParam;
    }
  }

  // Pass 2: drop oldest non-recent messages
  const dropCount = result.length - keepRecent;
  for (let i = 0; i < dropCount && result.reduce((n, m) => n + (m.content?.length ?? 0), 0) > budget; i++) {
    const removed = result.shift()!;
    // Re-encode the eviction notice so the model knows something was removed
    if (removed.role !== 'tool') {
      result.unshift({
        role: 'user',
        content: `[older message dropped from context to fit budget — key info preserved in recent messages]`,
      } as ChatCompletionMessageParam);
    }
  }

  if (system) result.unshift(system);
  return result;
}
```

### 2. Wire `contextCompression` in `agentLoop.ts`

In `buildMessages()`, check `cfg.get<string>('contextCompression')`:
- `'auto'` → apply budget as above (silent eviction).
- `'manual'` → skip eviction, but log a warning to the output channel when total chars > budget, so the user can start a new chat.

```ts
const compression = cfg.get<string>('contextCompression') ?? 'auto';
// ... existing code ...
if (compression === 'auto') {
  messages = enforceBudget(messages, BUDGET, MIN_RECENT);
} else {
  const totalLen = messages.reduce((n, m) => n + (m.content?.length ?? 0), 0);
  if (totalLen > BUDGET) {
    console.warn(`[fibonacci-agent] Context large (${totalLen.toLocaleString()} chars). Start a new chat or switch to auto compression.`);
  }
}
```

### 4. Throttle large state pushes in `webviewProvider.ts`

`pushFullState()` is called on every tool-start/tool-end/message-update. When `this.history` is large, serializing and `postMessage`-ing the full array repeatedly freezes the webview.

Add a dirty-flag + rAF throttle:

```ts
private statePushQueued = false;

private pushFullState(): void {
  if (this.statePushQueued) return;
  this.statePushQueued = true;
  setTimeout(() => {
    this.statePushQueued = false;
    const state: AgentState = { /* same as today */ };
    this.post({ type: 'STATE', state });
  }, 50); // 50ms de-bounce
}
```

This collapses rapid-fire state updates into a single message without perceptible UI lag.

### 5. Cap per-message payload for history entries in globalState

`saveCurrentToHistory()` (`webviewProvider.ts:303–327`) stores the full `this.history` array. A 200-message conversation with large tool results can bloat `globalState`. Cap each saved message's `content` to **50 000 chars** before persisting:

```ts
const cappedMessages = entry.messages.map(m => ({
  ...m,
  content: typeof m.content === 'string' && m.content.length > 50_000
    ? m.content.slice(0, 50_000) + '\n[...truncated in saved history...]'
    : m.content,
}));
const entry: ChatHistoryEntry = { ...entry, messages: cappedMessages };
```
