# Fix: Extension Screen Goes Black After Extended AI Conversation

## Root Cause Analysis

The black screen is caused by **multiple compounding issues**, with one primary and several contributing factors:

### Primary: No React Error Boundaries
Any rendering error in any component (especially `Markdown.tsx` parsing arbitrary AI output) causes React to unmount the entire component tree. The `#root` div becomes empty + `body { overflow: hidden }` = black/blank screen.

### Contributing: No Throttling on Streaming Updates  
Every single SSE token triggers: `postMessage` -> Zustand `updateMessage` (creates new array via `.map()`) -> React re-render -> `parseBlocks()` on entire accumulated content. At 100+ tokens/sec, this freezes the UI, making it appear black.

### Contributing: Unbounded Memory Growth
`this.history[]` grows without limit. No context compression is implemented despite `contextCompression` config existing. With long conversations, the postMessage payloads become very large.

## Implementation Plan (4 steps, ordered by priority)

### Step 1: Add React Error Boundary (CRITICAL — prevents black screen)

**New file: `src/webview/components/ErrorBoundary.tsx`**
- Class component with `getDerivedStateFromError` + `componentDidCatch`
- Shows a recovery UI with error message and "Try Again" button
- Uses VS Code CSS variables for styling

**Modify: `src/webview/main.tsx`**
- Wrap `<App />` in `<ErrorBoundary>` inside `<React.StrictMode>`

**Modify: `src/webview/components/Markdown.tsx`**
- Wrap `parseBlocks(content)` in try/catch — fallback to raw text on parse failure
- Wrap each block render in try/catch — show `[render error]` for individual failed blocks

**Modify: `src/webview/components/MessageBubble.tsx`**
- Wrap each `MessageBubble` in `<ErrorBoundary>` so one bad message doesn't kill the whole chat
- Rename existing implementation to `MessageBubbleInner`, wrap with boundary

### Step 2: Throttle Streaming Updates (HIGH — prevents UI freeze)

**Modify: `src/webviewProvider.ts`**
- Add a `streamingTimers: Map<string, ReturnType<typeof setTimeout>>` class property
- In `onAssistantContent` callback (line 79): throttle `post({ type: 'MESSAGE_UPDATE' })` to at most once per 100ms per message ID
- Still update `msg.content` immediately (the mutation is fine), just delay the postMessage

### Step 3: Memoize Markdown + Optimize Store Updates (MEDIUM — reduces re-render cost)

**Modify: `src/webview/components/Markdown.tsx`**
- Wrap component export with `React.memo` so unchanged content doesn't re-parse

**Modify: `src/webview/store/useStore.ts`**
- Optimize `updateMessage` to use `findIndex` + single-spread instead of `.map()` over entire array

### Step 4: Fix Auto-Scroll During Streaming (LOW — UX improvement)

**Modify: `src/webview/components/Chat.tsx`**
- Add last message content length to scroll effect dependencies so chat scrolls during streaming, not just when new messages are appended
